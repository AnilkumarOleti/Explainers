Embedding search · relevance filtering

The Cosine Adapter

A cosine adapter is a small network that reads a search query and converts that query's cosine similarity scores into probabilities of relevance. The scores then share one scale, so a single cutoff can drop irrelevant results for every query.

In short: it moderates the marks before anyone applies a pass mark.

Embedding search has no natural stopping point

Keyword search stops by itself: if a product doesn't contain the words, it isn't returned. Embedding search doesn't. You turn the query into a vector, ask the ANN index for the top K nearest items, and you get K items back every time. That happens even when only one of them is any good.

The obvious fix is a score cutoff: drop anything with cosine similarity below, say, 0.70. That fails because a cosine score only means something relative to other scores for the same query. Dual encoders are trained with contrastive or listwise losses, which reward "the right item scores higher than the wrong ones" and never say how high "high" is. A specific query can put its junk at 0.78. A broad query can put its best match at 0.64.

Think of two examiners. One marks harshly and one marks generously. A 62 from the first may be a better answer than a 75 from the second. A single pass mark applied to raw marks is unfair to both. You first need to moderate each examiner's marks onto a common scale.

The idea: learn each query's conversion curve

The cosine adapter is that moderation step. It looks at the query embedding and predicts the shape of a curve that maps this query's raw cosine scores to a probability that an item is relevant. After conversion, 0.5 means the same thing for every query, so one global threshold works.

What's inside

The adapter is small. It takes the query embedding the search system has already computed and passes it through a few feed-forward layers with ReLU activations. It outputs just three numbers.

Θ = (a, b, k) = CosineAdapter(query embedding)
F(x) = sgn(x) · a · |x|k + b   // x = raw cosine
P(relevant) = σ(F(x))   →   keep if P ≥ t

  1. a sets how steep the curve is: how quickly a small cosine gap becomes a big change in confidence.

  2. b shifts the curve left or right. It decides where this query's 50/50 point falls on the cosine axis.

  3. k bends it. It is squeezed into (0, 2) with 2σ(·), so the curve can be concave, straight or convex.

The curve is monotonic by design, so it never reorders results. An item that ranked third on cosine still ranks third. The adapter only decides where to cut the list. That keeps recall safe, and the re-ranker downstream still handles ordering.

Curve shapes the authors tried

The differences between the shapes were small. Power won narrowly on MS MARCO. Square root was the version deployed at Walmart. The large gain comes from making the curve depend on the query, not from the exact shape.

How it's trained

The dual encoder is frozen. Only the adapter's layers learn. Each training example is a query–item pair with a relevance label. The loss is ordinary binary cross-entropy on σ(F(cos)), so the output is literally trained to be a probability.

At Walmart, human raters labelled 6 million query–product pairs across 700k queries as exact (1), substitute (0.5) or irrelevant (0). Giving substitutes half credit worked better than treating them as negatives. The encoder itself had been trained on engagement data such as clicks. The adapter adds a different signal, human-judged relevance, without retraining the encoder.

Same encoder, same index. You only bolt a calibrator onto the side.

Why this rather than something heavier

ApproachHow it decides the cutCost per query
Raw cosine cutoffOne fixed number for every queryO(K)
Max-normalised cutoffDivide by the query's top score, then cutO(K)
Ranked-list truncation (e.g. Choppy)Transformer reads the whole score list and predicts a cut positionO(K²·d)
Cross-encoder classifierScores every query–item pair with a full modelK model calls
Cosine adapterQuery-specific curve, one global probability thresholdO(d²) once + O(K)

The adapter runs once per query, not once per item. Calibrating K scores is a few arithmetic operations each. It fits between retrieval and re-ranking, so the re-ranker gets a shorter and cleaner list.

Where it slips

With the cutoff tuned for 95% recall, some relevant items still get cut. The queries that lose them share a pattern: rare words, rare brand names, numbers and misspellings. Examples from the paper are "what is einstein neem oil good for" and "sydeny climate". The adapter only sees the query embedding. When the encoder doesn't understand the query well, the adapter can't tell how the scores should be read.

It is also tied to one encoder. Retrain or swap the dual encoder and the cosine scales shift, so the adapter has to be retrained on that dataset too.

Not to be confused with

"Cosine adaptation" also appears in LLM fine-tuning papers such as LoCA and MaCP. There it refers to the discrete cosine transform, used as a LoRA-style way to parameterise weight updates. It shares a word with the cosine adapter and nothing else.
